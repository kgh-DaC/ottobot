# Otto Fat 통신 프로토콜 (version 1)

기준 파일은 `protocol/protocol.json` 하나다. `firmware/otto_fat/protocol.h`와 `web/js/protocol.js`는 `gen_protocol.py`가 만든 생성물이므로 손으로 고치지 않는다. 이 문서는 사람이 읽기 위한 설명이고, 이 문서와 JSON이 다르면 JSON이 맞다. 동작 규칙(상태 머신, 자동 반응, 타이밍)은 `docs/behavior.md`에 있다.

## 1. 전송 계층

| 항목 | 값 |
|------|----|
| 물리 경로 | BLE 모듈 `otto2` ↔ SoftwareSerial D11(RX)/D12(TX), USB `Serial`(디버그용) |
| 속도 | 9600bps 8N1 (약 960 B/s) |
| 줄 끝 | `\n` (`\r`은 무시) |
| 최대 줄 길이 | 48바이트(`\n` 포함). 넘으면 `e 4 0`을 보내고 다음 `\n`까지 버린다 |
| 토큰 | 첫 글자 1개. 명령(웹→로봇)은 대문자, 메시지(로봇→웹)는 소문자 |
| 인자 | 공백 구분, 10진 정수만. 문자열 인자는 맨 마지막 하나만(줄 끝까지) |
| 값 범위 | 모든 정수 필드는 int16(−32768~32767) 안에 든다 |
| BLE 분할 | BLE 패킷은 최대 20바이트. 웹이 한 줄을 20바이트 단위로 나눠 쓴다. 수신 notify 조각은 이어 붙여 `\n`으로 자른다. 펌웨어는 UART만 보므로 분할을 알 필요가 없다 |

BLE 서비스는 `0xFFE0`, 특성은 `0xFFE1`(notify + write-without-response)을 기본 후보로 한다(가정). 연결 시 실제 서비스 목록을 로그로 남긴다.

## 2. 명령 (웹 → 로봇)

"최악 길이"는 `\n`을 포함한 바이트 수다. 20을 넘는 명령은 BLE 패킷 2개로 나뉜다.

| 이름 | 토큰 | ASCII | 인자 (범위, 기본값) | 최악 길이 | 응답 순서 |
|------|------|-------|----------------------|-----------|-----------|
| PING | `P` | 80 | 없음 | 2 | `a 80` → `i ...` → `c ...` → `d 80` |
| STOP | `S` | 83 | 없음 | 2 | `a 83` → (움직이던 중이면 `d 77`) → `d 83` |
| MOVE | `M` | 77 | id 0~20, period 400~3000 (1000), size 5~40 (15) | 13 | `a 77` → … 멈출 때 `d 77` |
| GESTURE | `H` | 72 | id 1~13 | 5 | `a 72` → (끝나면) `d 72` |
| SING | `K` | 75 | id 1~19 | 5 | `a 75` → `d 75` |
| TONE | `T` | 84 | freq 31~5000 Hz, ms 10~2000 | 12 | `a 84` → (재생 끝) `d 84` |
| MOUTH | `L` | 76 | id 0~30 | 5 | `a 76` → `d 76` |
| MATRIX | `X` | 88 | r0~r7 각 0~255 | 34 | `a 88` → `d 88` |
| TEXT | `W` | 87 | text 문자열 최대 9자 | 12 | `a 87` → (스크롤 끝) `d 87` |
| ARMS | `A` | 65 | left 0~180, right 0~180 | 10 | `a 65` → `d 65` |
| SERVO | `G` | 71 | yl, yr, rl, rr 각 0~180 | 18 | `a 71` → `d 71` |
| TRIM | `C` | 67 | yl, yr, rl, rr 각 −90~90, save 0~1 (1) | 20 | `a 67` → `c ...` → `d 67` |
| TELEM | `R` | 82 | interval_ms 0~5000 | 7 | `a 82` → `d 82` |
| AUTO | `U` | 85 | mask 0~15 | 5 | `a 85` → `i ...` → `d 85` |

명령별 보충:

- **MOVE** id는 Otto_APP move 표다: 0 home(1회성: `a 77` → 홈 → `d 77`), 1 전진, 2 후진, 3 좌회전, 4 우회전, 5 위아래, 6/7 문워크 좌/우, 8 스윙, 9/10 크루사이토 앞/뒤, 11 점프, 12/13 날갯짓 앞/뒤, 14 까치발 스윙, 15/16 굽히기 좌/우, 17/18 다리 흔들기 좌/우, 19 떨기, 20 상승 회전. period는 한 주기 ms, size는 동작 크기(h).
- **GESTURE** 1 Happy, 2 SuperHappy, 3 Sad, 4 Sleeping, 5 Fart, 6 Confused, 7 Love, 8 Angry, 9 Fretful, 10 Magic, 11 Wave, 12 Victory, 13 Fail.
- **SING** 1~19는 Otto 라이브러리 노래 번호(1 S_connection, 2 S_disconnection, 3 S_surprise, 4 S_OhOoh, 5 S_OhOoh2, 6 S_cuddly, 7 S_sleeping, 8 S_happy, 9 S_superHappy, 10 S_happy_short, 11 S_sad, 12 S_confused, 13~15 S_fart1~3, 16~18 S_mode1~3, 19 S_buttonPushed).
- **MATRIX** row0 = 맨 위 행, 각 행의 bit7 = 정면에서 본 왼쪽 칸. 웹 편집기 좌표 (x, y)는 `r[y]`의 `bit(7-x)`.
- **TEXT** `W` 다음 공백 하나 뒤부터 줄 끝까지가 문자열이다(공백 포함 가능). Otto `writeText`는 9자까지, 문자는 `0-9`, `A-Z`, 공백, `:;<=>?@[`만 표시한다. 웹은 대문자로 바꿔 보낸다. 펌웨어는 소문자가 와도 대문자로 바꾼다.
- **SERVO** 각도는 트림 적용 전 논리 각도(90 = 홈). 연속 MOVE 중이면 MOVE를 끝내고 적용한다.
- **TRIM** save=1이면 EEPROM 0~3(Otto 형식)에 저장, save=0이면 RAM에만 적용(미리보기). 생략하면 1. 적용 후 홈 자세로 간다. 현재 저장값은 YL −10, YR 0, RL 0, RR 0.
- **TELEM** 0 = 끔(부팅 기본값). 1~99는 100으로 올림. MOVING 중에는 실제 주기를 최소 500ms로 늦춘다(이유: behavior.md 7절).
- **AUTO** 비트 1 터치 정지, 2 장애물 후퇴, 4 넘어짐 감지, 8 소리 반응. 센서가 없는 비트(초음파 없음 → 2, MPU 없음 → 4)는 조용히 빠진다. 실제 적용값은 뒤따르는 INFO의 `auto` 필드로 확인한다. 부팅 기본값은 `7 & 가용 센서`.

## 3. 메시지 (로봇 → 웹)

| 이름 | 토큰 | 필드 | 최악 길이 | 설명 |
|------|------|------|-----------|------|
| INFO | `i` | proto, fw_build, sensors, auto | 15 | proto = 프로토콜 버전(1). fw_build = 펌웨어 빌드 번호(정수). sensors 비트 1 MPU6050, 2 초음파. auto = 실제 적용 중인 AUTO 마스크 |
| TRIMS | `c` | yl, yr, rl, rr | 18 | 현재 트림(RAM 값). PING, TRIM 응답에 포함 |
| ACK | `a` | cmd | 5 | 명령 검증 완료, 실행 **전**에 보냄 |
| DONE | `d` | cmd | 5 | 실행 완료. ACK를 받은 명령마다 정확히 한 번 |
| ERR | `e` | code, cmd | 7 | 거부(ACK·DONE 없음) 또는 실행 중 센서 오류(cmd 0) |
| TELEMETRY | `t` | dist_cm, touch, pitch, roll, sound, state | 24 | 주기 상태. dist_cm 0 = 측정 실패·센서 없음 |
| EVENT | `v` | kind, value | 9 | 자동 반응·센서 이벤트 |

텔레메트리 필드 범위: dist_cm 0~400, touch 0/1, pitch −90~90, roll −180~180, sound 0~1023(A6 원시값), state = 상태 코드.

토큰이 아닌 줄(예: 펌웨어 디버그 출력)은 웹 `parseLine()`이 `RAW`로 돌려준다. 펌웨어 디버그 출력은 USB로만, 메시지 토큰 글자로 시작하지 않게 쓴다(`#`으로 시작 권장).

### 대역 계산 (9600bps ≈ 960 B/s)

| 흐름 | 바이트/줄 | 횟수/초 | B/s | 대역 비율 |
|------|-----------|---------|-----|-----------|
| TELEMETRY 최소 주기 100ms (최악 길이) | 24 | 10 | 240 | 25% |
| TELEMETRY 권장 250ms | 24 | 4 | 96 | 10% |
| TELEMETRY MOVING 중(≥500ms) | 24 | 2 | 48 | 5% |
| EVENT·ACK·DONE (드묾) | ≤9 | ~2 | ~18 | 2% |

최악 조합(100ms 텔레메트리 + 이벤트)도 30% 한도 안이다. 웹 기본값은 250ms를 권장한다.

## 4. 코드 표

### 오류 (`e code cmd`)

| 코드 | 이름 | 언제 |
|------|------|------|
| 1 | UNKNOWN_CMD | 첫 글자가 명령 토큰이 아님. cmd = 그 글자의 ASCII |
| 2 | BAD_ARG | 인자 개수 부족·초과, 정수 아님, 범위 밖 |
| 3 | BUSY | AVOID(장애물 후퇴) 중에 동작 명령이 옴, 또는 자동 정지 직후 MOVE 잠금(1000ms) 중에 MOVE가 옴(`e 3 77`) |
| 4 | LINE_TOO_LONG | 48바이트 넘는 줄. cmd = 0 |
| 5 | SENSOR_FAIL | 실행 중 MPU6050 I2C 통신 실패가 이어져 넘어짐 감지를 끔. cmd = 0 |
| 6 | FALLEN | FALLEN 상태에서 서보를 쓰는 명령이 옴 |

### 이벤트 (`v kind value`)

| 코드 | 이름 | value |
|------|------|-------|
| 1 | TOUCH | 1 (눌림 시작) |
| 2 | OBSTACLE | 거리 cm |
| 3 | FALL | 기준을 넘은 축의 각도(부호 포함, 절댓값이 큰 쪽) |
| 4 | RECOVER | 0 = 자세 회복, 1 = AUTO에서 넘어짐 감지를 꺼서 강제 해제 |
| 5 | SOUND | A6 측정값 |
| 6 | BOOT | sensors 비트(INFO와 같음) |

### 상태 (TELEMETRY state)

| 코드 | 이름 | 뜻 |
|------|------|----|
| 0 | IDLE | 대기 |
| 1 | MOVING | 연속 MOVE 반복 중 |
| 2 | ACTION | 1회성 블로킹 동작(제스처·노래·텍스트·home) 중 |
| 3 | FALLEN | 넘어짐 — 서보 해제 |
| 4 | AVOID | 장애물 후퇴 중 |

## 5. 시리얼 모니터 예시 대화

Arduino IDE 시리얼 모니터(9600, "새 줄" 줄끝)로 USB에서 그대로 시험할 수 있다. `>`는 보낸 줄, `<`는 받은 줄이다.

부팅과 연결 확인 (초음파 없음, MPU 있음):
```
< i 1 1 1 5
< v 6 1
> P
< a 80
< i 1 1 1 5
< c -10 0 0 0
< d 80
```
`sensors=1`(MPU만), `auto=5`(터치 1 + 넘어짐 4, 장애물 비트는 센서가 없어 빠짐).

전진하다 멈추기:
```
> M 1 1000
< a 77
> S
< a 83
< d 77
< d 83
```

연속 MOVE 교체(전진 중 좌회전으로):
```
> M 1
< a 77
> M 3 1200
< a 77
```
앞 MOVE의 `d 77`은 오지 않는다. 동작이 실제로 멈출 때 한 번만 온다.

MOVE keepalive와 통신 끊김 감시(웹이 500ms마다 같은 MOVE를 재전송, 이후 연결이 끊김):
```
> M 1
< a 77
> M 1
< a 77
> M 1
< a 77
   (1500ms 넘게 수신 없음 → 현재 주기가 끝난 뒤 정지)
< d 77
```

전진 중 제스처(MOVE가 끝나고 제스처가 실행됨):
```
> H 11
< a 72
< d 77
< d 72
```

텔레메트리 켜기:
```
> R 250
< a 82
< d 82
< t 0 0 1 -2 53 0
< t 0 0 0 -1 52 0
```

AUTO 요청에 없는 센서 비트가 섞인 경우:
```
> U 15
< a 85
< i 1 1 1 13
< d 85
```
13 = 1 + 4 + 8. 장애물(2)은 초음파가 없어 적용되지 않았다.

트림 미리보기 후 저장:
```
> C -8 0 0 0 0
< a 67
< c -8 0 0 0
< d 67
> C -8 0 0 0
< a 67
< c -8 0 0 0
< d 67
```

넘어짐과 회복:
```
< v 3 72
> M 1
< e 6 77
> L 5
< a 76
< d 76
< v 4 0
```

오류:
```
> Q
< e 1 81
> M 25
< e 2 77
> X 1 2 3
< e 2 88
```

## 6. 변경 이력

### version 1 (2026-11-24) — 첫 확정

`.claude/skills/otto-protocol/references/protocol-baseline.json`에서 출발했다. 아직 배포된 펌웨어가 없으므로 version은 1로 둔다. 기준안 대비 변경점과 이유:

| 변경 | 이유 |
|------|------|
| TEXT `maxlen` 20 → 9 | Otto 라이브러리 `writeText()`가 최대 9자만 표시한다(`Otto.cpp`). 20자를 허용하면 웹이 보낸 글자가 말없이 잘린다 |
| TRIM에 `save` 인자 추가 (0~1, 기본 1) | 웹 보정 화면에서 슬라이더를 움직일 때마다 EEPROM에 쓰지 않고 미리보기할 수 있게. 생략 시 기준안과 동작이 같다. 최악 길이 20바이트로 BLE 패킷 1개에 들어간다 |
| 메시지 TRIMS(`c`) 추가 | 웹이 현재 트림(YL −10)을 모르면 보정 화면이 0에서 시작하고, 한 축만 고쳐 보내도 YL 트림이 0으로 덮인다. PING·TRIM 응답에 포함 |
| INFO에 `auto` 필드 추가 | 초음파가 없어 AUTO 비트가 빠지는 경우와 재연결 시 웹 토글을 실제 상태에 맞추기 위해. AUTO 응답에도 INFO를 다시 보낸다 |
| ACK/DONE/ERR 규칙 명확화 | "ACK를 받은 명령은 DONE이 정확히 한 번", "ERR = 거부이며 ACK·DONE 없음"(센서 오류 cmd 0 제외). 모든 명령이 DONE을 보내므로 웹은 명령 종류와 상관없이 같은 방식으로 완료를 기다린다 |
| desc 보강 (STOP·MOVE·TONE·TELEM·MATRIX·ARMS·SERVO) | FALLEN 중 STOP, MOVE id 0, TONE 비블로킹, MOVING 중 텔레메트리 감속 등 동작 규칙을 생성물 주석에도 남김. 토큰·인자 순서 변경은 없다 |
| MOVE 통신 끊김 감시(watchdog) 추가 — 동작 규칙만, 형식 변경 없음 | 리더 결정. BLE가 끊기면 연속 MOVE가 멈추지 않던 위험 해소. MOVING 중 1500ms(`MOVE_WATCHDOG_MS`) 넘게 올바른 줄이 없으면 펌웨어가 STOP처럼 처리(홈, `d 77`, IDLE). 웹은 MOVE 유지 중 같은 MOVE를 500ms마다 재전송(period > 1500이면 `ceil(period/3)`ms). 재수신은 교체 규칙대로 `a 77`만, 주기가 끊기지 않는다. 판정은 주기 종료 후, 실효 정지 지연 ≤ period + 1500ms. 상세는 behavior.md 6절 |
| 센서 판정·loop 순서 규칙 갱신 — 동작 규칙만, 형식 변경 없음 | 리더 결정(펌웨어 QA 4차: 블로킹 동작 중 loop 간격 = period라 넘어짐·터치 감지가 늦음). ① 넘어짐: 정지 상태는 필터 + 60° 300ms 유지, MOVING·AVOID는 주기 끝 원시 샘플로 60° 2회 연속 또는 75° 1회면 즉시 FALLEN(최악 지연 ≈ period × 2). ② 터치: 첫 HIGH에서 10ms × 3회 재샘플로 확정, 한 주기 안에 눌렀다 뗀 터치는 놓칠 수 있음. ③ 터치 정지 확인음 1500Hz 80ms(비블로킹). ④ loop 순서: 수신(STOP 즉시) → 센서 갱신 → 안전 판정 → 명령 실행 → motion. ⑤ PING은 얼굴을 바꾸지 않음. 상세는 behavior.md 2·3·4·8절 |
| 자동 정지 후 MOVE 잠금 추가 — 동작 규칙만, 기존 코드 BUSY 사용 | 리더 결정(통합 QA r1: 터치 정지 직후 버퍼에 남은 keepalive MOVE가 수락돼 다시 걸음). 터치 정지·장애물 후퇴 종료·watchdog 정지 직후 `MOVE_LOCKOUT_MS`(1000ms) 동안 MOVE는 `e 3 77`로 거부, 시간 만료로만 해제. STOP·비이동 명령은 정상. 웹은 TOUCH 이벤트나 요청하지 않은 `d 77`에서 hold·keepalive를 멈추고, 잠금 중 `e 3 77`은 조용히 무시. 상세는 behavior.md 1·3·4·6절 |
