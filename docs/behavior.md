# Otto Fat 동작 명세 (protocol version 1)

이 문서는 펌웨어가 "언제 무엇을 하고 무엇을 보내는가"를 정한다. 명령 형식은 `docs/protocol.md`, 값 범위는 `protocol/protocol.json`이 기준이다. 웹 데모 모드(가상 로봇)도 이 문서대로 흉내 낸다.

**가정**이라고 표시한 항목은 요구사항에 없거나 실물에서 확인되지 않아 설계자가 정한 기본값이다. 펌웨어는 이 값들을 `config.h` 상수로 두고, 하드웨어 시험 결과에 따라 바꾼다(프로토콜 변경 아님).

## 1. 상태 머신

| 코드 | 상태 | 뜻 | 서보 |
|------|------|----|------|
| 0 | IDLE | 대기. 홈 자세 또는 마지막 SERVO/ARMS 자세 | 붙음 |
| 1 | MOVING | 연속 MOVE를 한 주기씩 반복 | 붙음 |
| 2 | ACTION | 1회성 블로킹 동작(GESTURE, SING, TEXT, MOVE 0 home, SERVO 보간, TRIM 홈 이동) | 붙음 |
| 3 | FALLEN | 넘어짐 감지. 다리·팔 서보 모두 detach | 해제 |
| 4 | AVOID | 장애물 후퇴 동작 중 | 붙음 |

```
            M id(1~20)                    STOP / 터치정지 / 다른 1회성 명령
   IDLE ───────────────────▶ MOVING ───────────────────────────────▶ IDLE
    │ ▲                        │  장애물(전진 계열, AUTO 2)
    │ │ 끝                     ▼
    │ └──────────── ACTION   AVOID ── 후퇴 끝 / STOP ──▶ IDLE
    │  H K W G C M0 ─▶ ACTION
    │
    └─ (어느 상태든, AUTO 4) 넘어짐 60°·300ms ─▶ FALLEN ── 25°·1s 유지 ──▶ IDLE
```

전이 규칙:

| 현재 | 계기 | 다음 | 보내는 것 |
|------|------|------|-----------|
| IDLE | `M 1~20` | MOVING | `a 77` |
| IDLE | `M 0`, `H`, `K`, `W`, `G`, `C` | ACTION → IDLE | `a` → (실행) → `d` |
| MOVING | 다른 `M 1~20` | MOVING(교체) | `a 77`만. 앞 MOVE의 `d 77`은 없음 |
| MOVING | `S` | IDLE | `a 83`, `d 77`, (홈) `d 83` |
| MOVING | `M 0`, `H`, `K`, `W`, `G`, `C` | ACTION → IDLE | `a xx`, `d 77`, (실행) `d xx` |
| IDLE | 터치(AUTO 1) | ACTION → IDLE | `v 1 1`, (기쁨 제스처 → `HELLO` 흐르기 → 원위치, 약 6.5초) — a/d 없음 |
| MOVING | 터치(AUTO 1) | IDLE + MOVE 잠금 | `v 1 1`, (확인음, 홈) `d 77` |
| MOVING | 감시: 1500ms 넘게 올바른 줄 없음(주기 종료 후 판정) | IDLE + MOVE 잠금 | (홈) `d 77` |
| MOVING(전진 계열) | 장애물(AUTO 2) | AVOID | `v 2 cm`, `d 77` |
| AVOID | 후퇴 끝 | IDLE + MOVE 잠금 | 없음 |
| AVOID | `S` | IDLE | `a 83`, (홈) `d 83` (`d 77`은 AVOID 진입 때 이미 보냄) |
| AVOID | 터치(AUTO 1) | IDLE + MOVE 잠금 | `v 1 1` (확인음, 홈) |
| 아무 상태 | 넘어짐(AUTO 4, 3절 상태별 판정) | FALLEN | `v 3 각도`, 움직이던 중이면 `d 77` |
| FALLEN | 회복 조건 | IDLE | `v 4 0` |
| IDLE(MOVE 잠금 중) | `M` (id 0 포함) | IDLE | `e 3 77` (BUSY, 실행 안 함). 잠금은 `MOVE_LOCKOUT_MS` 경과로만 풀림 |
| FALLEN | `U`로 비트 4 해제 | IDLE | `a 85`, `v 4 1`, `i ...`, `d 85` |

## 2. 자동 반응 우선순위

**넘어짐 > 터치 > 장애물 > 명령.** STOP은 명령 중 최우선이며 어떤 상태에서도 받지만, FALLEN은 풀지 않는다(넘어진 로봇을 STOP으로 일으키면 안 된다).

`loop()` 한 바퀴의 순서:

1. **수신**: BT, USB 각각 줄 조립·검증. 완성된 줄은 도착 순서대로 큐에 넣는다. **STOP은 이 단계에서 즉시 반영**한다(MOVE·AVOID 중단 플래그, TONE 중단, 홈, `d 83`).
2. **센서 갱신**: IMU 샘플, 터치 확인(첫 HIGH면 재샘플 확정), 초음파(있을 때·간격 경과 시), 사운드 피크.
3. **안전 판정**: 넘어짐 → 터치 정지 → 장애물 순. 넘어짐이 성립하면 FALLEN 전이 후 터치·장애물은 동작을 일으키지 않는다(터치 이벤트만). 터치 정지가 성립하면 장애물 동작은 건너뛴다. MOVE 감시(watchdog) 판정도 여기서 한다.
4. **명령 실행**: 큐의 명령 처리(ACK → 실행 → DONE).
5. **motion**: MOVE 다음 한 주기 또는 AVOID 다음 걸음 실행(블로킹). 이어서 텔레메트리 주기 확인, TONE 종료 확인.

같은 바퀴에서 여러 조건이 겹치면 높은 쪽만 동작으로 이어진다. 이벤트(`v`)는 각 조건이 성립할 때 하나씩 나갈 수 있다.

AUTO 마스크 비트: 1 터치 정지, 2 장애물 후퇴, 4 넘어짐 감지, 8 소리 반응. **부팅 기본값 `7 & 가용 센서`**(소리 반응은 꺼짐 — 서보 소음 오반응 방지, 가정).

## 3. 타이밍·임계값

| 항목 | 값 | 비고 |
|------|----|------|
| 넘어짐 판정 (IDLE 등 정지 상태, ACTION 종료 후) | 필터 값 \|pitch\| > 60° 또는 \|roll\| > 60° 가 300ms 이상 지속 | 히스테리시스 |
| 넘어짐 판정 (MOVING·AVOID) | 주기(걸음) 끝 **원시 샘플** \|pitch\| 또는 \|roll\| > 60° 가 2회 연속, 또는 단일 샘플 > 75° → 즉시 FALLEN | 최악 감지 지연 ≈ period × 2 |
| 회복 판정 | \|pitch\| < 25° 그리고 \|roll\| < 25° 가 1000ms 이상 지속 | |
| IMU 샘플 주기 | 20ms (50Hz), MOVING 중에는 주기 사이에만 | 블로킹 동작 중에는 읽지 못함 |
| IMU 필터 | `f = f*0.8 + new*0.2` | sensors.md |
| IMU pitch 0점 보정 | **−6°** (바로 선 상태 원시 pitch ≈ +6°) | roll 보정 0° |
| IMU 축·부호 | 앞으로 기울면 pitch +가 되도록 `config.h` 상수 | **가정**: 원시 ax 기반 pitch를 그대로 쓰고, 부호는 하드웨어 시험에서 확인 |
| 장애물 트리거 | 거리 중앙값 1~10cm (0 제외) | |
| 장애물 해제(재무장) | 중앙값 > 15cm 또는 0 | 해제 전에는 이벤트 반복 없음 |
| 초음파 측정 | 60ms 간격, 최근 3회 중앙값, `pulseIn` 타임아웃 25ms | sensors.md |
| 장애물 후퇴 동작 | 뒤로 2걸음(`walk` 방향 −1, period 1000), 끝나면 홈 | **가정** |
| 전진 계열 MOVE | id 1(전진), 9(크루사이토 앞), 12(날갯짓 앞) | **가정**: 이 id에서만 AVOID로 전이 |
| 터치 확정 | 처음 HIGH를 본 순간 10ms 간격 3회 재샘플(≤30ms), 모두 HIGH면 눌림 확정 | loop 속도와 무관. 눌림 시작에 이벤트 1회 |
| 터치 정지 확인음 | 1500Hz 80ms, 비블로킹 `tone()` | DONE 없음(명령이 아님) |
| 소리 임계값 | A6 > 70 | **가정**: 배경 51~54라 ref의 55는 너무 가까움 |
| 소리 쿨다운 | 이벤트 후 2000ms, 동작 종료 후 500ms 무시 | **가정** |
| 텔레메트리 주기 | 0(끔, 부팅 기본) 또는 100~5000ms. MOVING 중 최소 500ms | 7절 |
| SERVO 보간 시간 | 300ms | **가정** |
| MOVE 감시(watchdog) `MOVE_WATCHDOG_MS` | 1500ms | MOVING 중 올바른 줄이 이 시간 넘게 없으면 STOP 처리(6절) |
| MOVE 잠금 `MOVE_LOCKOUT_MS` | 1000ms | 자동 정지(터치 정지, 장애물 후퇴 종료, watchdog 정지) 직후. 4절 |
| 웹 MOVE keepalive 주기 | 500ms (단, period > 1500이면 `ceil(period/3)`ms, 최대 1000ms) | 6절 |
| I2C 타임아웃 | `Wire.setWireTimeout(3000, true)` (3ms) | 하드웨어 제약 7 |
| 팔 기본 각도 | 좌 90°, 우 90° | **가정**(요구사항): 하드웨어 시험 때 조정 |

## 4. 자동 반응 상세

### 넘어짐 (AUTO 4, MPU 필요)
- 성립: 3절 조건. 판정 각도는 0점 보정 후 값.
- 동작: 진행 중 MOVE/AVOID 중단 → 다리 4개 + 팔 2개 detach → 입모양 xMouth(26, **가정**) → `v 3 각도`(기준을 넘은 축 중 절댓값이 큰 값, 부호 포함) → 움직이던 중이면 `d 77`.
- 회복: 회복 조건 성립 → attach → 홈 자세, 팔 90° → 입모양 smile(10) → `v 4 0` → IDLE.
- **판정 방식은 상태에 따라 다르다.** 블로킹 동작 중에는 loop 간격이 period만큼 길어 "필터 + 300ms 지속" 규칙이 사실상 수 초 지연되기 때문이다.
  - IDLE 등 정지 상태(ACTION이 끝난 뒤 포함): 20ms 샘플, 필터 값으로 60° 300ms 규칙.
  - MOVING·AVOID: 주기(AVOID는 걸음) 끝마다 원시 샘플 1개(필터 거치지 않음, 0점 보정은 적용)로 판정. 60° 초과가 2회 연속이거나 한 샘플이 75° 초과면 즉시 FALLEN. 최악 감지 지연 ≈ period × 2(최대 약 6초). 주기 끝 샘플은 보행 진동을 포함하므로 2회 연속 조건으로 오탐을 줄인다.
- ACTION(제스처·노래·텍스트 등 블로킹) 중에는 감지할 수 없다. 동작이 끝난 뒤 정지 상태 규칙으로 판정된다.

### 터치 반응 (AUTO 1): 움직이는 중 정지, 멈춰 있으면 인사
- 확정 방식: loop에서 처음 HIGH를 본 순간 10ms 간격으로 3회 다시 읽어(최대 30ms) 모두 HIGH면 눌림으로 확정한다. loop 간격과 무관하게 같은 기준이다. 떼어짐(LOW)을 본 뒤에야 다음 눌림을 받는다.
- 눌림 확정마다 `v 1 1`을 보낸다. AUTO 1이 꺼져 있어도 이벤트는 보낸다(웹 표시용).
- AUTO 1이 켜져 있고 MOVING 또는 AVOID면: 동작 중단 → 확인음(1500Hz 80ms, 비블로킹) → 홈 → `d 77`(MOVING일 때만) → IDLE.
- AUTO 1이 켜져 있고 IDLE이면(2026-11-26 추가): `v 1 1` 뒤 **인사** — 기쁨 제스처(GESTURE 1, OttoHappy) → 매트릭스에 `HELLO` 흐르기 → 얼굴 복원 → 다리 원위치(`motion_rehome()`: 라이브러리 '쉬는 중' 상태를 풀고 홈 90°+트림, 팔 기본). 상태는 ACTION, 약 6.5초 블로킹이며 a/d 응답은 보내지 않는다(명령이 아님). 그동안 받은 줄은 끝난 뒤 처리된다. 웹은 IDLE에서 `v 1 1`을 받으면 약 8초 동안(또는 다음 텔레메트리까지) ACK 대기 시간을 늘린다. 제스처·글자는 `config.h` `TOUCH_GREET_GESTURE`·`TOUCH_GREET_TEXT`, 구현은 `commands_greet()`.
  - Flash 한도(30,720B) 때문에 USB 부팅 진단 줄을 `# Otto fat fw 1` 고정 문자열로 줄였다. 센서 유무는 `i`·`v 6` 줄로 본다.
- ACTION·FALLEN에서는 이벤트만(확인음·인사 없음).
- **물리적 한계**: 터치는 loop가 돌 때만 읽는다. 블로킹 1주기(MOVE period, 제스처 등) 안에 눌렀다 뗀 터치는 놓칠 수 있다. 확실히 멈추려면 한 주기 이상 누르고 있어야 한다.

### 장애물 후퇴 (AUTO 2, 초음파 필요)
- 측정은 초음파가 있을 때만 한다(없으면 `pulseIn` 25ms 블로킹을 아예 하지 않는다).
- 트리거 조건이 처음 성립하면 상태와 관계없이 `v 2 cm`을 1회 보낸다(FALLEN 제외). 해제 조건 전까지 다시 보내지 않는다.
- AUTO 2가 켜져 있고 전진 계열 MOVE 중이면: MOVE 중단, `d 77`, AVOID 진입 → 뒤로 2걸음(걸음 사이에 입력·넘어짐·터치 확인) → 홈 → IDLE.
- AVOID 중 STOP·터치는 즉시(걸음 경계에서) 중단한다. 동작 명령은 `e 3 cmd`(BUSY)로 거부한다.

### 자동 정지 후 MOVE 잠금 (MOVE lockout)
- **이유**: 자동 정지 순간 수신 버퍼에는 웹이 이미 보낸 keepalive MOVE가 남아 있을 수 있다. 그대로 수락하면 터치로 멈춘 로봇이 곧바로 다시 걷는다(통합 QA r1 결함).
- **대상(자동 정지)**: 터치 정지(MOVING·AVOID), 장애물 후퇴 종료(AVOID → IDLE, 후퇴가 정상으로 끝났을 때와 터치로 끊겼을 때 모두), MOVE watchdog 정지. 사용자 STOP과 넘어짐은 대상이 아니다(넘어짐은 FALLEN 거부 규칙이 따로 있다).
- **규칙**: 자동 정지가 끝난 시각(홈 자세 후 IDLE 전이 시점)부터 `MOVE_LOCKOUT_MS`(기본 1000ms, `config.h`) 동안 MOVE(`M`, id 0 포함)는 검증 단계에서 `e 3 77`(BUSY)로 거부하고 실행하지 않는다. ACK·DONE은 없다.
- STOP과 MOVE 외 명령(`P S H K T L X W A G C R U`)은 잠금과 무관하게 정상 처리한다. 잠금 중 STOP도 잠금을 풀지 않는다. **잠금은 시간 만료로만 풀린다.** 잠금 중 다시 자동 정지가 일어나지는 않으므로(IDLE) 연장도 없다.
- **웹 의무**: `v 1 1`(TOUCH)을 받거나, 요청하지 않은 `d 77`(자동 정지)을 받으면 이동 버튼 hold를 해제하고 keepalive를 즉시 멈춘다. 재개는 사용자가 버튼을 다시 눌러야 한다. 잠금 중 받은 `e 3 77`은 조용히 무시한다(오류 토스트 없음). 잠금 중 사용자가 다시 누르면 잠금 종료 후 재시도하거나 "잠시 후 다시 누르세요"를 안내한다. 웹은 잠금 시작을 자동 정지 메시지 수신 시각으로 추정한다.

### 소리 반응 (AUTO 8, 선택)
- IDLE에서만, 쿨다운 밖에서 A6 > 임계값이면 `v 5 값` → 입모양 bigSurprise(14) 1초 후 이전 입모양으로(**가정**: 움직임 없음).

## 5. 센서 부재 시 동작

부팅 시 감지 결과가 INFO `sensors` 비트와 BOOT 이벤트 value에 들어간다.

| 센서 | 감지 방법 | 없을 때 |
|------|-----------|---------|
| MPU6050 (비트 1) | WHO_AM_I(0x75) = 0x68 (0x70·0x72 클론도 허용) | pitch·roll = 0 전송, AUTO 비트 4 강제 제외, FALLEN 없음 |
| 초음파 (비트 2) | 부팅 시 60ms 간격 5회 측정이 모두 0 | dist_cm = 0 전송, AUTO 비트 2 강제 제외, 측정 자체를 하지 않음 |
| 터치·사운드 | 감지 불가(항상 있다고 봄) | — |

- 현재 실물은 초음파가 응답하지 않으므로 `sensors = 1`, 기본 `auto = 5`가 예상값이다.
- 초음파 재감지는 재부팅 때만 한다(**가정**: 사용자가 배선을 고친 뒤 리셋).
- 실행 중 MPU 읽기가 3회 연속 실패(I2C 타임아웃)하면: `e 5 0` → sensors 비트 1 제거, AUTO 비트 4 제거 → FALLEN이었다면 강제 회복(`v 4 1`) → `i ...` 재전송.
- `U` 명령에 없는 센서 비트가 있으면 그 비트만 빼고 적용하고 ERR은 보내지 않는다. 실제 값은 `i`의 `auto`로 알린다.

## 6. 명령 처리 규칙

### ACK/DONE 시점
- 줄을 받으면 **검증(토큰·인자 개수·정수·범위·상태 허용) → 통과 시 즉시 ACK → 실행 → DONE**.
- 검증 실패 시 ERR만 보내고 아무것도 실행하지 않는다(ACK·DONE 없음).
- ACK를 보낸 명령은 정확히 한 번 DONE을 보낸다. 중단돼도 보낸다.
- 즉시 명령(`P L X A R U`)은 같은 루프에서 DONE. `P`는 ACK와 DONE 사이에 `i`, `c`를, `U`는 `i`를, `C`는 `c`를 보낸다.
- 블로킹 명령(`H K W M0 G C`)은 동작이 끝난 직후 DONE.
- `T`는 비블로킹(`tone()`). 재생 시간이 지난 뒤 첫 루프에서 DONE. 재생 중 새 `T`나 `S`가 오면 앞 소리를 끊고 앞 `T`의 DONE을 보낸다(순서: 새 명령 ACK → 앞 `d 84`).
- 빈 줄은 무시(응답 없음). 소문자 명령 토큰은 UNKNOWN_CMD.
- 48바이트를 넘는 줄은 `e 4 0` 후 다음 `\n`까지 버린다.

### 연속 MOVE
- MOVE는 Otto 함수를 `steps = 1`로 한 주기씩 호출하고, 주기 사이마다 입력과 센서를 확인한다. 따라서 STOP 반응 지연은 최대 한 주기(period, 최대 3000ms)다.
- MOVING 중 새 MOVE(같은 id 포함)는 ACK 후 다음 주기부터 새 값으로 바꾼다. `d 77`은 동작이 실제로 멈출 때 한 번만 보낸다.
- **같은 MOVE의 재수신(keepalive)도 이 교체 규칙으로 처리한다**: `a 77`만 나가고 `d 77`은 나가지 않는다. 진행 중 주기를 끊거나 처음부터 다시 시작하지 않고, 홈 자세를 거치지 않으며, 다음 주기부터 (같은) 새 파라미터로 이어 간다. 동작이 끊겨 보이면 안 된다.
- MOVING 중 1회성 동작 명령(`M 0 H K W G C`)은 MOVE를 끝내고(`d 77`) 실행한다. 순서: `a xx` → `d 77` → 실행 → `d xx`.
- MOVING 중 즉시 명령(`P L X A T R U`)은 MOVE를 멈추지 않는다.
- 웹은 키를 누를 때 MOVE 1번, 뗄 때 STOP 1번을 보낸다. 운영체제 키 반복 이벤트로 MOVE를 보내지 않는다. 대신 아래 keepalive만 보낸다.

### 통신 끊김 감시 (MOVE watchdog)
- **규칙**: 상태가 MOVING인 동안, 어느 포트(BT·USB)에서도 **올바른 줄**(검증을 통과해 ACK를 받은 줄)을 `MOVE_WATCHDOG_MS`(기본 1500ms, `config.h`) 넘게 받지 못하면 펌웨어가 STOP과 같은 처리를 한다: MOVE 중단 → 다리 홈, 팔 90° → `d 77` → IDLE. STOP 명령이 아니므로 `a 83`/`d 83`은 보내지 않는다. 이벤트 코드는 추가하지 않는다(웹은 요청하지 않은 `d 77`로 정지를 안다).
- ERR을 받은 줄, 빈 줄, 깨진 줄은 수신으로 치지 않는다. MOVE 외의 올바른 명령(`P`, `L` 등)도 수신으로 인정한다.
- 감시는 MOVING에만 적용한다. IDLE·ACTION·AVOID·FALLEN에는 적용하지 않는다(AVOID는 2걸음 후 스스로 끝남). MOVING 진입(`a 77`) 순간 타이머를 0으로 둔다.
- **판정 시점**: 한 주기는 블로킹이라 그동안 루프가 줄을 읽지 못한다. 감시 판정은 **주기가 끝나고 입력을 모두 읽은 뒤** 한다. 주기 중 SoftwareSerial 버퍼(또는 USB 버퍼)에 쌓여 있던 줄도 그때 읽혀 수신으로 인정된다. 수신 시각은 줄을 읽은 시각으로 기록한다.
- 따라서 통신이 끊긴 뒤 실제로 멈추기까지의 **실효 지연 ≤ period + 1500ms**(최악 3000 + 1500 = 4.5초). 감시가 판정되기 전에 시작된 주기는 끝까지 실행된다.
- **웹 의무(keepalive)**: 연속 MOVE를 유지하는 동안 마지막으로 보낸 MOVE와 같은 줄을 500ms마다 다시 보낸다. 사용자가 방향을 바꾸면 그 MOVE가 새 keepalive 대상이다. STOP을 보내면 keepalive를 멈춘다. 연결이 끊기면 웹은 보낼 수 없으므로 펌웨어 감시가 정지를 맡는다.
- **수신 버퍼 주의(설계자 제안)**: 주기 중에는 바이트가 64바이트 SoftwareSerial 버퍼에만 쌓인다. period 3000ms에 500ms keepalive면 한 주기에 MOVE 6줄(최악 13B × 6 = 78B)이 쌓여 버퍼가 넘치고, 뒤에 온 STOP이 잘릴 수 있다. 그래서 웹은 keepalive 간격을 `max(500, ceil(period/3))`ms(period 3000 → 1000ms)로 둔다. 한 주기에 최대 3줄(39B) + STOP(2B) = 41B로 버퍼 안에 들고, 간격이 1000ms 이하라 1500ms 감시에도 걸리지 않는다. period 1500ms 이하에서는 500ms 그대로다.

### 블로킹 동작 중 입력
- GESTURE·SING·TEXT·home·SERVO 보간 동안에는 입력을 읽지 못한다. 그동안 들어온 바이트는 SoftwareSerial 64바이트 버퍼에 쌓였다가 끝난 뒤 순서대로 처리된다(STOP도 이때 처리).
- 웹은 블로킹 명령의 DONE을 받기 전에는 STOP 외의 명령을 보내지 않는다.

### 상태별 허용 명령

| 상태 | 허용 | 거부 (ERR) |
|------|------|-----------|
| IDLE, MOVING | 전부 | — |
| IDLE(자동 정지 후 MOVE 잠금 중) | `M` 외 전부 | `M` → `e 3 77` (BUSY) |
| AVOID | `P S T L X R U` | `M H K W G A C` → `e 3 cmd` (BUSY) |
| FALLEN | `P S T K L X W R U` | `M H G A C` → `e 6 cmd` (FALLEN) — 서보를 쓰는 명령 |

- FALLEN 중 `S`: `a 83` → `d 83`. 서보는 해제된 채, 상태는 FALLEN 유지.
- FALLEN 중 `U`로 비트 4를 끄면 즉시 회복 처리(attach, 홈, `v 4 1`) 후 IDLE.

### STOP 처리
`a 83` → MOVE·AVOID 중단(진행 중이면 `d 77`) → 재생 중 TONE 중단(`d 84`) → 다리 홈, 팔 90° → `d 83`. IDLE에서도 같은 순서(홈 자세 복귀).

## 7. 응답 경로 (USB / BT)

- 펌웨어는 BT(SoftwareSerial D11/D12)와 USB(`Serial`) 두 곳에서 같은 프로토콜을 받는다. 줄 버퍼는 포트마다 따로(각 48바이트).
- **ACK/DONE/ERR/INFO/TRIMS 응답은 명령이 들어온 포트로만** 보낸다.
- **TELEMETRY·EVENT는 "활성 포트"로** 보낸다. 활성 포트 = 마지막으로 올바른 줄을 받은 포트, 부팅 기본은 BT.
- 부팅 시 `i ...`와 `v 6 sensors`는 두 포트 모두로 보낸다.
- 디버그 출력은 USB로만, `#`으로 시작한다(웹 `parseLine()`에서 RAW로 처리됨).
- USB(COM10, FTDI 호환칩)는 유휴 시 드라이버가 마지막 데이터를 반복하는 문제가 있다. 웹의 기본 경로는 BT다. USB로 웹을 시험하면 같은 줄이 반복 수신될 수 있다(QA 항목).
- 텔레메트리를 MOVING 중 최소 500ms로 늦추는 이유: SoftwareSerial 송신은 바이트마다 약 1ms 동안 인터럽트를 막아 Servo(Timer1) 펄스를 흔든다. 24바이트 줄 하나가 약 25ms 동안 인터럽트를 막는다.

## 8. 부팅 순서

1. `Serial.begin(9600)`, BT `begin(9600)`.
2. `Otto.init(2, 3, 4, 5, true, ...)` — EEPROM 0~3 트림(YL −10, YR 0, RL 0, RR 0) 로드. 홈 자세.
3. 팔 D6·D7 attach, 90°.
4. LED 매트릭스(A1/A2/A3, Orientation 1) 초기화.
5. I2C 초기화(100kHz, 와이어 타임아웃) → WHO_AM_I 확인 → MPU 레지스터 설정.
6. 초음파 감지(5회).
7. AUTO = 7 & 가용 센서, TELEM = 0.
8. 입모양 smile, 짧은 부팅음(S_connection, **가정**).

첫 PING(연결)을 포함해 PING은 얼굴(입모양·매트릭스)을 바꾸지 않는다. 연결 표시가 필요하면 웹이 MOUTH/MATRIX를 명시적으로 보낸다.
9. 두 포트로 `i 1 <build> <sensors> <auto>`, `v 6 <sensors>`.

## 9. 메모리 관련 규칙

- 줄 버퍼 2개 × 48바이트, 문자열은 `F()`/PROGMEM, `String` 클래스 금지, `sprintf`에 `%f` 금지(정수만).
- RAM 사용 75%(1536B) 이하. 포트별 줄 버퍼 외 큰 버퍼를 두지 않는다.
