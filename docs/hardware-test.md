# Otto 하드웨어 시험 (로봇 앞에서 순서대로)

대상: Arduino Nano(Optiboot) + 펌웨어 `firmware/otto_fat` + 웹 `web/`. 상수는 모두 `firmware/otto_fat/config.h`.
항목마다 "할 일 → 기대 결과 → 다르면". 막히면 그 항목에서 멈추고 아래 단계로 넘어가지 말 것.

## 0. 준비
- 로봇을 **발이 바닥에 안 닿게 들거나 받침 위**에 둔다(1~6번 시험 중 의도치 않게 걸을 수 있다).
- Chrome 또는 Edge. 웹은 `python -m http.server 8000 -d web` 후 `http://localhost:8000`. `file://`은 안 된다.
- 다른 기기(휴대폰)가 otto2에 연결돼 있으면 끊는다.

## 1. 업로드
- 할 일: `python .claude/skills/otto-firmware/scripts/compile.py --sketch firmware/otto_fat --upload --port COM10` (기본 FQBN `arduino:avr:uno`). **nano 정의로 빌드하지 않는다**(Flash 30,720B 초과, uno 정의 32,256B 기준 94%).
- 기대: `[compile] 성공 (경고 0건)`, Flash 약 30590 B(94%), 업로드 완료.
- 다르면: sync 오류 → 구형 부트로더. `OTTO_FQBN=arduino:avr:nano:cpu=atmega328old`로 시도하되 Flash가 넘치면 기능을 줄여야 한다. 포트가 안 보이면 케이블·COM 번호·시리얼 모니터를 닫았는지 확인.

## 2. 부팅 확인
- 할 일: 전원을 켜고(또는 리셋) 시리얼 모니터 9600bps. 입모양과 소리를 본다.
- 기대: 웃는 입모양 + 부팅음, 시리얼에 `# Otto fat fw 1` 한 줄과 `i ...`, `v 6 ...`. IMU 있음. 초음파 유무는 `v 6 <sensors>`(1 = MPU만, 3 = MPU+초음파)로 본다(2026-11-26 Flash 절약으로 부팅 줄에서 US 제거). auto 5(터치+넘어짐).
- 다르면: `IMU none` → MPU6050 배선(SDA A4, SCL A5), `IMU_ADDR`. 입모양이 없으면 `PIN_MTX_*`, `MTX_INTENSITY`. 소리가 없으면 `PIN_BUZZER`. `touch 1`로 계속 찍히면 터치센서 극성(`PIN_TOUCH`, 눌림 HIGH).
- 시리얼 모니터에서 `P` 입력 → `a 80`, `i ...`, `c -10 0 0 0`(트림, TRIMS), `d 80`이 와야 한다. (`t ...`는 텔레메트리로, `TELEM`을 켰을 때만 온다.)

## 3. 웹 실행·BLE 연결
- 할 일: 웹 열기 → 연결 → BLE → 목록에서 `otto2` 선택. 로그 창을 연다.
- 기대: 로그에 `서비스 <uuid>: <특성들>` 줄과 `UART 사용: <라벨> — 수신 ..., 송신 ...`. 연결 뒤 INFO가 표시되고 상태가 "연결됨"이 된다. 서비스 UUID(예: FFE0)를 **여기에 적어 둔다**: ______
- 다르면: "UART 특성을 찾지 못했습니다" → 로그의 서비스 UUID를 `web/js/ble-transport.js`의 `UART_CANDIDATES`에 추가. 목록에 otto2가 없으면 "모든 기기 보기" 켜기. 연결이 즉시 끊기면 다른 기기 연결 해제 후 로봇 전원 재투입.
- 20바이트 넘는 명령 확인: 매트릭스(5번)를 보내 로그에 `X ...`(34B)와 `a 88`·`d 88`이 오면 분할 전송 정상.

## 4. 서보·팔·트림
- 할 일: 웹 보정 화면에서 다리 4개 서보 각각을 한 번씩 움직인다(± 값). 팔 슬라이더 좌/우를 움직인다. 홈 버튼.
- 기대: 서보 이름과 실제 부위 일치, 홈에서 두 발이 평행·몸이 똑바로. 팔 90°가 팔을 **내린** 자세.
- 다르면: 다리 서보가 서로 바뀜 → `PIN_YL/YR/RL/RR`. 팔 좌우 바뀜 → `PIN_ARM_L/R`. 팔 90°가 내린 자세가 아님 → `ARM_REST_L/R`.
- 트림: 홈에서 비뚤면 트림을 조정 → 저장. 전원을 껐다 켜도 유지돼야 한다(EEPROM 0~3). 기본 YL −10.
- 확인: 걷기 중 팔을 움직인 뒤 방향키를 놓아 보면(STOP) 슬라이더가 90°로 돌아가고 실제 팔도 90°로 와야 한다.

## 5. 매트릭스
- 할 일: 매트릭스 편집기에서 왼쪽 위 한 점만 켜고 전송. 입모양 번호와 TEXT도 보낸다.
- 기대: 정면에서 보아 **왼쪽 위**가 켜진다. 글자가 읽히는 방향.
- 다르면: 좌우 반전 → `MTX_FLIP_X 1`, 상하 반전 → `MTX_FLIP_Y 1`, 90° 회전 → `MTX_ORIENTATION`. 밝기 → `MTX_INTENSITY`, 글자 속도 → `TEXT_SCROLL_SPEED`.

## 6. 터치
- 할 일: IDLE에서 터치센서 누름 → 로그의 `v 1 1`. 이어서 방향키(전진)를 누른 채 터치.
- 기대: 누를 때마다 웹에 터치 표시와 `v 1 1`. IDLE에서는 기쁨 제스처(소리·몸 흔들기) 뒤 매트릭스에 `HELLO`가 흐르고, 끝나면 다리가 원위치(홈)로 돌아온다(약 6.5초). 웹에 "터치! 로봇이 기쁨 제스처 후 HELLO 인사" 토스트, 그동안 누른 버튼은 끝난 뒤 실행(빨간 오류 없음). 전진 중에는 짧은 "삑"(1500Hz 80ms) 후 홈 자세로 멈추고 `d 77`, "터치로 멈췄습니다" 토스트.
- 주의: 한 주기(기본 1초) 안에 눌렀다 떼면 놓칠 수 있다. 주기 이상 누른다.
- 다르면: 항상 눌림/안 눌림 → `PIN_TOUCH` 극성. 두 번 찍힘/떨림 → `TOUCH_RESAMPLE_N`, `TOUCH_RESAMPLE_MS`. 확인음 → `TOUCH_BEEP_HZ/MS`.

## 7. 기울기 부호
- 할 일: 텔레메트리를 켜고(웹 센서 화면) 로봇을 바로 세워 pitch/roll이 0 근처인지 본 뒤, **앞으로** 기울이고, 다음 **오른쪽**으로 기울인다.
- 기대: 바로 선 상태 pitch·roll ±3° 이내, 앞으로 기울이면 pitch **+**.
- 다르면: 바로 선 값이 어긋남 → `IMU_PITCH_OFFSET`/`IMU_ROLL_OFFSET`. 앞으로 기울이는데 − → `IMU_PITCH_SIGN -1`. 롤 부호 → `IMU_ROLL_SIGN`. pitch와 roll이 뒤바뀜 → `IMU_PITCH_AXIS`/`IMU_ROLL_AXIS`(0=ax,1=ay,2=az), `IMU_UP_AXIS`.

## 8. 넘어짐·회복
- 할 일: 손으로 로봇을 옆으로 눕혀 0.5초 이상 유지.
- 기대: 서보 힘 풀림(detach), 입모양 X(26), 웹에 넘어짐 배너와 `v 3 각도`. 이 상태에서 MOVE는 `e 6`(웹 "넘어졌습니다" 안내). 다시 세워 1초 유지하면 서보 attach, 홈, 웃는 얼굴, `v 4 0`.
- 걷는 중에도 눕혀 본다: 주기 한두 번 안에 FALLEN(`d 77`).
- 다르면: 감지 안 됨 → `FALL_DEG`(60), `FALL_HOLD_MS`, 센서 부호·축(7번). 걷기만 해도 넘어짐 오탐 → `FALL_DEG`/`FALL_INSTANT_DEG` 올리기, `FALL_MOVING_SAMPLES` 늘리기. 회복이 안 됨 → `RECOVER_DEG`, `RECOVER_HOLD_MS`. 입모양 → `FALL_MOUTH`.

## 9. 방향키 누른 채 터치 (MOVE 잠금)
- 할 일: 로봇을 바닥에 두고 웹 전진 키/버튼을 **누른 채** 로봇 머리를 터치(1초 이상 누름). 터치 뒤에도 키를 계속 누르고 있는다.
- 기대: 터치 순간 로봇이 멈추고 **다시 걷지 않는다**. 웹은 "로봇이 터치를 감지해 스스로 멈췄습니다..." 토스트, 키 상태 해제. 로그에 `v 1 1`, `d 77`, 이후 keepalive가 더 이상 나가지 않는다. 손을 떼고 1.2초 지나 다시 누르면 걷는다. 1초 안에 다시 누르면 "잠시(1초) 이동을 받지 않습니다" 안내 뒤 잠금이 끝나면 걷는다. **빨간 오류 토스트는 없어야 한다.**
- 다르면: 멈춘 뒤 한 번 더 걸으면 잠금 실패 → 로그에서 터치 직후 `M ...`에 `e 3 77`이 오는지 확인(펌웨어 `MOVE_LOCKOUT_MS`, 기본 1000). 잠금이 길어 답답하면 `MOVE_LOCKOUT_MS` 줄이되 웹 `web/js/link.js`의 `MOVE_LOCK_MS`도 같이 맞춘다. 오류 토스트가 뜨면 로그의 `e` 코드를 기록.

## 10. watchdog (블루투스 끊기)
- 할 일: 전진 키를 누른 채, 웹 탭을 닫거나 PC 블루투스를 끈다(또는 로봇을 연결 범위 밖으로).
- 기대: 최대 약 1.5초 + 한 주기 안에 로봇이 홈 자세로 멈춘다(계속 걷지 않음). 다시 연결하면 정상, 연결 직후 1초 안의 MOVE는 `e 3 77`로 거부될 수 있으나 웹이 알아서 기다린다.
- 다르면: 계속 걷는다 → `MOVE_WATCHDOG_MS` 확인, 시리얼 USB로 `S` 입력해 정지(위험 시 전원 스위치). 정상 연결 중 이유 없이 멈춘다 → BLE 지연, `MOVE_WATCHDOG_MS` 늘리기(period 3000이면 특히).

## 11. 초음파 (현재 불량)
- 할 일: 부팅 로그의 `US` 항목 확인.
- 기대(현재): `US none`, 웹 센서 카드 "센서 없음", 장애물 자동 반응 옵션 비활성. 걷기에 영향 없음.
- 수리 후: `US 25cm`처럼 거리가 나오고, 손을 앞 10cm 이내에 대면 `v 2 cm`, 전진 중이면 뒤로 2걸음 후 홈(그 사이 이동 명령은 BUSY). 같은 거리에서 이벤트가 반복되지 않아야 한다(15cm 밖으로 가야 재무장). 수리 후 후퇴 종료 직후 방향키 재입력(잠금)도 다시 확인한다.
- 다르면: `PIN_TRIG`(8), `PIN_ECHO`(9), `OBST_TRIGGER_CM`, `OBST_RELEASE_CM`, `AVOID_STEPS`, `US_TIMEOUT_US`.

## 12. 전원
- 할 일: 걷기 + 팔 동작 + 제스처를 연속으로 실행. 배터리 전압이 낮은 상태에서도 반복.
- 기대: 리셋·재부팅(부팅음이 다시 남, 웹에 BOOT 토스트) 없음. 블루투스 끊김 없음.
- 다르면: 서보 동시 구동 시 리셋 → 전원 용량·굵은 배선, 서보 전원과 Nano 5V 사이 콘덴서(470~1000uF). 걷는 중 수신이 끊김 → SoftwareSerial 수신 손실(서보 인터럽트): `BT_BAUD` 9600 유지, 배선 짧게.
